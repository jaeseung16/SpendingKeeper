## Overview

SpendingKeeper is a native iOS app (SwiftUI + SwiftData) for tracking spending. Published on the App Store (`com.resonance.SpendingKeeper`). Swift 6.0, iOS deployment target 26.0. There is no Package.swift — this is an Xcode project (`SpendingKeeper.xcodeproj`) with dependencies managed via Swift Package Manager inside Xcode.

The project does **not** use Xcode's file-system-synchronized groups, so creating a new source file on disk is not enough — it must be registered in `SpendingKeeper.xcodeproj/project.pbxproj` (a `PBXBuildFile` entry, a `PBXFileReference` entry, membership in its `PBXGroup`, and the target's `PBXSourcesBuildPhase`) or it won't compile. The simplest way is to add the file through Xcode; if editing `project.pbxproj` directly, mirror an existing sibling file in the same group and use fresh unique 24-character hex IDs.

## Build / Test Commands

The only shared scheme is `SpendingKeeper`. Use `xcodebuild` (replace the simulator name with one available via `xcrun simctl list devices`):

```bash
# Build
xcodebuild -project SpendingKeeper.xcodeproj -scheme SpendingKeeper \
  -destination 'platform=iOS Simulator,name=iPhone 16' build

# Run all tests (unit + UI)
xcodebuild -project SpendingKeeper.xcodeproj -scheme SpendingKeeper \
  -destination 'platform=iOS Simulator,name=iPhone 16' test

# Run a single test (class/method via -only-testing: Target/Class/method)
xcodebuild -project SpendingKeeper.xcodeproj -scheme SpendingKeeper \
  -destination 'platform=iOS Simulator,name=iPhone 16' \
  test -only-testing:SpendingKeeperTests/SpendingKeeperTests/testLatestStatementDateOne
```

Unit tests use **XCTest** (not Swift Testing) and run against an in-memory `ModelContainer`. There is no linter configured.

## Architecture

### Data layer (SwiftData)
All persistent models live in `Model/` and are prefixed `SK`. The schema is registered in `SpendingKeeperApp.swift` and consists of: `SKAccount`, `SKRecord`, `SKSnapshot`, `SKSnapshotSpending`, `SKSnapshotIncome`, `SKSnapshotRecord`. Other `SK*` files in `Model/` are plain value types / enums (e.g. `SKTransaction`, `SKTrend`, `SKStats`, `SKPeriod`, `SKAccountStatementDay`) used by the view model and views, not stored.

Key modeling conventions:
- `@Model` classes carry a stable `uid`/`uuid: UUID` plus `created`/`updated` dates. Cross-references between records and accounts are by **`accountId: UUID?`**, not by SwiftData relationships — `SKRecord` is intentionally not linked to `SKAccount`; lookups go through a `FetchDescriptor` predicate on `uid` (see `ContentView.findAccount(of:)`).
- `SKSnapshot` is the exception: it owns its children (`records`, `incomes`, `spendings`) via `@Relationship(deleteRule: .cascade)`. A snapshot is a frozen denormalized copy of the records between two dates, generated by `SKViewModel.generateSnapshot`.

### View model
`SKViewModel` (an `ObservableObject`, injected via `.environmentObject`) holds the `ModelContext` and contains the app's business logic — trend statistics, statement-day math, snapshot generation, and CSV export. This is the most logic-heavy file and where most testable code lives. The Trends feature (`stats(...)`) computes spending for the current vs. previous period (day-over-month for daily, month-over-year for monthly) using `Calendar` enumeration; the date math here is subtle.

### Navigation
`SKNavigator` is a `@MainActor @Observable` singleton (`SKNavigator.shared`), injected via `.environment` and also registered with `AppDependencyManager` so AppIntents can drive navigation. `ContentView` is a 3-column `NavigationSplitView` keyed off `SKNavigator.menu` (an `SKMenu` enum: Transactions, Accounts, Trends, Snapshots, Import from Wallet). To trigger navigation programmatically (including from intents), call methods on the navigator rather than mutating view state.

### AppIntents (`AppIntents/`)
Siri/Shortcuts entry points. `SpendingKeeperAppShortcuts` registers the shortcuts; individual intents (`AddRecord`, `ImportFromWallet`, `OpenDailyTrend`) resolve `SKNavigator` via `@Dependency` and call its `navigateTo…` methods. When adding an intent that changes screens, add a corresponding navigation method on `SKNavigator`.

### FinanceKit (Import from Wallet)
The Apple Wallet import feature is gated behind `#if canImport(FinanceKit)` throughout (`ContentView`, `SKViewModel`, the `Imports*` views). Anything touching `FinanceKit.Transaction` must stay inside these guards so the project still compiles where FinanceKit is unavailable.

### Ads
Google Mobile Ads (AdMob) via SPM. `BannerAd` (`AdMob/`) is a `UIViewControllerRepresentable` shown at the bottom of `ContentView`, iOS-only (`#if os(iOS)`). App Tracking Transparency is requested on `didBecomeActive` before starting `MobileAds`. The ad unit ID is hardcoded in `BannerAd.swift`.

### Views (`View/`)
SwiftUI views grouped by feature with a consistent `…ListView` / `…RowView` / `…DetailView` / `Add…View` naming pattern (Account, Record, Snapshot, Trends, Imports). Snapshot detail can render charts and export a PDF (`Snapshot*PageView`, `ShareActivityView`).

## Conventions

- Versioning is managed in Xcode build settings (`MARKETING_VERSION` / `CURRENT_PROJECT_VERSION`); the README tracks a human-readable version history.
